## 結果を読むときの注意

- **規則 24 ℃ と既定制御は、両方のプラントで同じになった。** どちらの既定のスケジュールも、窓の間の冷房の設定値が 24 ℃ だからである（B は timeline の `setpoint` が 24.0 だけ、A は KPI の差が 1e-7 程度）。そのため、この 2 つの方式は区別できない。
- **移した MPC は、両方のプラントで、その場の MPC より電力が少なく、不快度が多い。** B では差がはっきりしている（不快度 +0.48 K·h、CI が 0 を含まない）。A は日による差が大きく、8/1 が 0.217 K·h である。
- **再学習（N=1）は、両方のプラントで電力が 7〜10 % 多い。** 不快度は 0 だった。設定値を 23.0〜23.5 ℃ に下げる提案をしていた（A と B の 7/24 の例）。
- 方式の比較は、BOS と Safety を通らないハーネスで行った。経路を通したときの一致は、live の 4 回で示す（未実行）。

## 走らせなかったもの

- **B の再学習 N=7。** B の励起のデータはちょうど 7 日（P7D）なので、最初の 7 日で学習すると holdout が 0 行になる。BDE の driver は「horizon 16 step の rollout に足りる行が無い」として、model を作らなかった（`retrain/b-n7/results.json`）。代わりに N=6.5 を回した（次の節）。
- live の 4 回（問い 1 と 2）。日ごとの承認が要る。
