## 1. 段 1 で分かったこと（この事前登録の前提）

- 事前登録 §3 の基準を満たす重みは無かった。B は 0.3 以上で内側の割合 1.0、A は最大 0.29。

## 2. 問い

在室の時間帯の行だけで学習した model では、両方のプラントで、§3 の基準を満たす罰の重みがあるか。

## 3. 手順（offline。live と人の承認は要らない）

1. **データ：** 段 1 と同じ run（A run 2、B run 1）と、同じ窓（[励起の開始, 開始 + 期間]）。
2. **行の絞り込み：** sim 時刻の現地時刻が 8:00 以上 18:00 未満の行だけを使う。
   - 現地時刻は、plant の `start_datetime` の UTC オフセットで決める（A は +09:00 の `SIM_EPOCH`、B は −07:00）。
   - 絞り込みは Testbed の driver が dataset の行に行い、学習は BDE の `train_dynamics` に渡す。
   - 1 歩先の教師（`<name>__next`、15 分先）は、絞る前に BDE が作ったものをそのまま使う。
3. **学習と holdout の分け方：** 段 1 と同じ。A は 1.5 日と 0.5 日、B は 5 日と 2 日。どちらも絞った後の行に当てる。
4. **replay：** [補遺](px4-stage1-addendum-replay.md) の手順と同じ（前回値は実際の設定値、16 周期、外気は固定、重みは 0.03／0.1／0.3／1.0、帯の制約の penalty だけを置き換える）。
   - 開始の state は、holdout の絞った後の行から、制御周期ごとに取る。
5. **指標：** 段 1 と同じ。holdout の 1 歩先の RMSE（変数ごと）、16 周期目と 1 周期目の内側の割合、帯の外の K·h、model の定常の利得（外気は holdout の中央値）。
6. **移転の検査：** BDE #928 が直るまでは実行しない。

## 4. 重みの選び方（§3 のまま）

- 両方のプラントで、16 周期目の内側の割合が 0.5 以上になる候補のうち、最も小さい重みを選ぶ。両方で同じ値にする。
- 当てはまれば、その重みと在室の時間帯の model を、段 2 の事前登録の入力にする。
- 当てはまらなければ、段 2 には進まない。

## 5. 結果を見る前に分かっている限界

- A の holdout（0.5 日）の在室の時間帯は、7 月 16 日の 12:25〜18:00 だけで、開始の state は約 22。B は 2 日分で約 80。
- 1 周期は 15 分、回すのは 4 h。18 時に近い開始では、回す途中で在室の時間帯を出る（model には時刻の入力が無い）。
- 時間帯の境界（8 時と 18 時）は、BOPTEST bestest_air と PX1 の在室のスケジュールに合わせた仮定である。実測の在室の点では分けていない。
- 段 2 では、MPC が在室の時間帯の外で動かないように、評価の窓を在室の時間帯の中に置く必要がある。
