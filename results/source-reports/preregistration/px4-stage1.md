# 事前登録：PX4 段 1、学習データと罰の重みの選定（探索的）（2026-11-07 起草、2026-11-08 確定）

**状態：確定（ユーザーの決定、2026-11-08。§6 はすべて推奨の案）。** sha256 は manifest の `px4-a-boptest-path` と `px4-b-px1-path` の `experiment.preregistration` に記録する。確定の後の変更は、新しい事前登録に探索として書く。段 1 は**探索的**で、結果で合否は決めない。段 2（評価）の事前登録は、段 1 の後に別に書く（計画 (`../px4-plan.md`, not exported) の段 2）。準備の記録は 段 1 の準備 (`../verification/2026-11-07-px4-stage1-preparation.md`, not exported)。

## 1. 問い

1. 共通の範囲（21〜27 ℃）と共通の変数（P4-D8）で、A（BOPTEST、10 倍速）と B（PX4 B の plant、60 倍速）の励起のデータが、Safety の経路で集まるか。
2. 集めたデータで学習した model と MPC について、罰の重みを変えたときに、提案が範囲の端に張り付かず内側に来るか。どの重みが段 2 に使えるか。
3. 移転の検査（`transfer_policy.py`：`training-range` → `check` → `build`）が、学習した model で通るか。

## 2. 構成

- configuration は `px4-a-boptest-path` と `px4-b-px1-path`（manifest）。BDE `5f36355`、ControlSpec は `-xfer` の 2 つ。
- 目的は、冷房とファンの電力の和に、帯 22〜24 ℃の soft 制約を加えたもの。`rate_limit` は 0.5 ℃/周期。

### 手順（直列。live は 1 度に 1 つ、BOPTEST の時間の主体は常に 1 つ）

1. 人の承認（準備の記録の 1 回目と 2 回目）。
2. **A の励起：** BOPTEST の proxy を 10 倍速（`--ai 5 --step 50`）で起動する。
   - 開始は BOPTEST の時刻 **16848000 s（7 月 15 日 0 時）**、warmup は 604800 s。
   - 段 21.0／22.5／24.0／25.5／27.0 ℃ を 3 sim h ずつ、seed 0、P2D（192 周期）続ける。
   - その後に release する。
3. **B の励起：** PX4 B の plant を 60 倍速で起動する。開始は 2019-07-15T00:00-07:00（PX1 と同じ）。同じ段で P7D（672 周期）続け、その後に release する。
4. **学習（offline、BDE の学習の経路）：**
   - その場の model：
     - A は 2 日のうち、最初の 1.5 日で学習し、残りの 0.5 日を holdout にする。
     - B は 7 日のうち、5 日で学習し、2 日を holdout にする（E2E-04 と同じ）。
   - 再学習（P4-D3）は、移転先のデータの最初の 1 日（A、B）と 7 日（B）を使う。
   - `training-range` で、学習時の action の範囲を測る。
5. **罰の重みの選定（offline、replay）：**
   - 候補は **0.03、0.1、0.3、1.0**。
   - 重みだけを変えた ControlSpec を、BDE の生成器の `--comfort-penalty` で作る。id は変わらない。
   - 学習した model と MPC に、holdout の state を与え、提案の分布を数える。
6. **移転の検査：** A→B と B→A の両方で、`check` と `build` を通す。拒否の理由はすべて記録する。

## 3. 指標（報告だけ。合否にしない）

| 指標 | 式 | 区間 |
|---|---|---|
| 励起の完了 | 提案のうち Safety が判定した割合、lake に読み戻せた割合（PX3 の `transactions.py`） | 各励起 |
| sim 時刻の品質 | `sim_time_quality` の `changed` の割合、巻き戻り、壁時計に対する傾き（`boptest_live.summarize_rows`） | 各励起。A の 10 倍速は初めて測る |
| model の精度 | holdout の 1 歩先の RMSE（室温 K、電力 kW） | holdout |
| 内側の割合 | 提案のうち `21.1 < u < 26.9` の割合（端から 0.1 K 以内を「張り付き」とする） | holdout、重みごと |
| 帯の外 | holdout の予測で室温が 22〜24 ℃の外になる K·h | holdout、重みごと |
| 移転の検査 | `check` の拒否の理由の数と種類 | A→B、B→A |

**重みの選び方：**
- 両方のプラントで、内側の割合が 0.5 以上になる候補のうち、最も小さい重みを選ぶ。
- 両方で同じ値にする（D3）。
- 当てはまる候補が無ければ、段 2 には進まず、目的を見直す。

## 4. データの扱い

- 補間しない。`sim_time_quality` が `changed` の行と、`sim_run_status` が `valid` でない行は、BDE の軸の規則で落とす。
- 励起の期間と、段 2 の評価の窓は重ねない。
- **評価の窓の候補：** 7 月 24 日〜8 月 6 日（A、B とも励起の後）の 1 日の窓を 5 つ以上。日は段 2 の事前登録で決める。
- 段 1 の replay に使う state は、holdout だけから取る。評価の窓からは取らない。

## 6. 決めたこと（ユーザー、2026-11-08。すべて推奨の案）

1. A の開始の時刻は 16848000 s（7 月 15 日）。B と同じ暦日にするため。BOPTEST の `time` の 0 が現地の標準時の 1 月 1 日 0 時であることは、確かめていない（PX3 A は 12650400 s で走った）。§7 の限界に置く。
2. A の期間は P2D。P4-D3 の「A は 1 日分」は再学習のときの話で、その場の model には 1 日では足りない見込み。
3. 重みの候補は 0.03、0.1、0.3、1.0。選び方は、内側の割合 0.5 以上で最も小さい重み。端から 0.1 K 以内を張り付きとする。
4. 学習の分け方は、A が 1.5 日と 0.5 日、B が 5 日と 2 日。

## 7. 結果を見る前に分かっている限界

- A の開始の暦日（7 月 15 日）は、BOPTEST の `time` の 0 を 1 月 1 日 0 時とした計算。違えば、A と B の天気の日はずれる（KPI はプラントの中の比なので、段 1 の判断は変わらない）。
- A の 10 倍速の励起は初めてで、sim 時刻の品質（`changed` の割合）がどうなるかは測っていない。
- B の plant は FCU ではなく、AHU＋VAV＋冷凍機。A の冷房の電力（FCU）と B の冷房の電力（冷凍機）は、同じ名前でも中身が違う（PX2 が測った差）。
- RI は main `8c87146`（P4-D7）。#629 で ingest のコードが変わったので、readback の遅れなどは PX3 の値と RI の SHA が違うものとして比べる。
