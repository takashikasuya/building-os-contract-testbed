# 事前登録の補遺：PX4 段 2 の B の再学習の N=7 を 6.5 日にする（2026-11-12）

[段 2 の事前登録](px4-stage2.md) §3 と、[前の補遺](px4-stage2-addendum-pin-points.md) への補遺である。

- **B の N=6.5 の run より前に commit する。** offline の他の方式（A 25 回、B 25 回）は、もう走らせて結果を見ている（[記録](../verification/2026-11-12-px4-stage2-offline.md)）。この変更はその結果を見た後に決めたので、B の N=6.5 は**探索的**として報告する。
- ユーザーの決定（2026-11-12、推奨の案 (a)）。

## 変えること

| 項目 | 前（§3） | 後 |
|---|---|---|
| B の再学習の N | 1 と 7 | 1 と **6.5** |

- 理由：B の励起のデータはちょうど 7 日（P7D）である。最初の 7 日で学習すると holdout が 0 行になり、BDE の driver が model を作らない（`artifacts/px4-stage2-offline-20261112/retrain/b-n7`：「horizon 16 step の rollout に足りる行が無い」）。
- 6.5 日にすると、学習は現地の 7 月 21 日 13:20 までになる。holdout は、在室の時間帯の 13:20〜18:00（PT5M で 56 行）である。rollout に要る 48 行（16 step × 3 行）を満たす。
- 「データのほぼ全部」という N=7 の意図に近く、BDE も Testbed の検査も変えずに済む。
- 学習の呼び方は N=1 と同じ（`run_bde_pipeline.py --train-s 561600 --local-hours 8:18`、BDE `5f36355`）。run も、他の方式と同じ窓とハーネスで行う。

## 変えないこと

- A の N=1、B の N=1、ほかの方式、窓、KPI、許容差。
